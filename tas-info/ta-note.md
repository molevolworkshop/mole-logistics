# Before MOLE

## Updating profile on the website

Once TAs get access (granted by the director(s)) to contribute to the GitHub repository of the MOLE website, the profiles of TAs/instructors available in the `faculty` folder in the [repository](https://github.com/molevolworkshop/molevolworkshop.github.io/tree/master/faculty) can be edited — good idea to keep the information up to date.

## Check course materials sheet

Ensure items used during the course are accounted for (either in storage or somebody is bringing them). Might be good to have somebody bring a portable speaker.

## Testing the tutorials

Once the testing version of the virtual machine (VM) is prepared, the lead TA can assign tutorials to each TA. Each TA is responsible for checking that their assigned tutorial works fine: for example, whether the required software is installed on the VM, the provided code in the tutorial executes without error, example data is uncorrupted, and the results and interpretation in the tutorial are consistent and make sense.

TAs can let the lead TA know when testing the assigned tutorials is complete. The lead TA should track progress. TAs can then try other tutorials that are not assigned to them — this will help TAs familiarize themselves with the other tutorials and also test whether they work on different machines/OSes. TAs should be familiar with the input commands and outputs so they can help others work through them.

If issues are identified, describe them in detail in the Slack channel. If the issue is related to the VM (e.g., software not installed), co-directors can fix it; otherwise, in cases like an analysis giving different results than the tutorial expects, let the instructor know so they can fix it.

It's better to complete this step sooner rather than later, to prevent last-minute changes to the VM.

## Sessions led by TAs

During the workshop, TAs have historically been responsible for leading four 90-minute sessions:

1. Introduction computing laboratory
2. Alignment lab
3. IQ-TREE introduction
4. IQ-TREE lab and quiz

Consult with the course directors to ensure this is still the expectation. Make sure at least one TA is responsible for each lab and ready to lead by course start.

Gather MOLE materials from wherever they are stored and take stock of anything missing or low. See the [materials sheet](materials.md) for items used during the workshop. Stock up on low supplies, drinks, and snacks prior to course start.

The classroom should have enough tables/chairs to seat ~60 people. Make sure tables are connected to electricity and that cables aren't a tripping hazard. Stock the classroom with batteries (AA for mic, AAA for laser pointers if desired), markers, and dry-erase cleaning fluid.

# Lab Notes

### Post-it system

Before the Intro Computing lab, TAs place one of each green (or blue/yellow) and pink post-it at each participant's desk. This is a good way to promote communication between the TAs and participants about how they're doing during the tutorial: green means the participant has completed the given task, and pink means they need help. They can stick the post-it on top of their laptop or at the edge of the table, wherever it's easily visible to TAs. Note: the post-its are not provided by MBL.

### Some (unexpected) confusions during the lab

1. Setting the VM passwords confused some participants. Although it's straightforward once you understand it, it helps to spell out the steps explicitly, for example:

    ```
    1. On a participant's terminal, type:
        $ ssh moleuser@123.123.123.123 (their personal IP)

    2. It will ask for a password, so type:
        Current password (which is given)
        Login success

    3. Then, once in the VM, type:
        $ passwd

    4. When the prompt asks for the current password, re-type the password used above.

    5. It will then ask for a new password. Here, the participant can set their own password.

    6. Re-type the new password; done.
    ```

2. If a student forgets the password they set, a TA can log in to their VM using the TA's local laptop (no password needed) and use the commands below. Because we become superuser with these commands, it won't ask for the old password, so you can type in a temporary password (e.g. `nobska@capecod`) twice and have the participant change it again to one they'll remember this time:

    ```
    sudo su
    passwd moleuser
    ```

3. It's important to stress that a dot (`.`) and double dots (`..`) mean something significant in Unix, which comes up in the Unix tutorial.

4. It's a good idea to stress being on the local machine when using `scp`.

5. Setting an `alias` for `moleuser@123.123.123.123` is a good idea. Most people pick it up easily by following the steps, but not everyone does.

6. It might be worth mentioning that there are third-party tools that combine a command-line interface with interactive file transfer. A participant suggested MobaXTerm (https://mobaxterm.mobatek.net), though it's unclear if it's available for Mac as well as Windows and Linux.

7. This tutorial looks easy but took almost the full 90 minutes in practice, with lots of confusion.

8. Mention using `tab` to autocomplete commands.

### Tree Comparison lab

Accessing some of the materials from the Open Tree of Life can be slow or break (both the website and the API). This seems to be an issue with the database rebuilding after certain actions, making the first calls to the site slow. Getting things built prior to the lab will make actions a bit faster.

Emily Jane McTavish ran this lab last year — coordinate with her (or whoever runs the lab) if this is still an issue, or if you encounter it while testing the labs.

# After MOLE 
In 2026 we ported our slack workspace to discord, since slack erases messages after 90 days. Steps:
1. [Created a fresh discord server] (https://support.discord.com/hc/en-us/articles/204849977-How-do-I-create-a-server) called mbl-mole-2026 after the slack workspace.

2. Used a tool called [slackdump](https://github.com/rusq/slackdump) to export the slack workspace. I did this instead of using slack's export button because I wanted to bring our files (paper pdfs and group photos) with me. Run it once to export the full workspace and make sure to change the default export storage type from mattermost to standard or your files will not transfer!! Probably a year from now there will be other arcane issues and back-incompatibilities. Claude helped me id this one for better or worse.. so I'm sure you can use ANTHROPIC RELIGION 5.2 or whatever it's called in 2027 to do the same. For now:
	Export > Export Options... > Export Storage Type > standard 
	Export > Run Export
	Emoji > Run Emoji #if you want to take the custom emojis with you too

3.1 Used a script that claude wrote for me (upload_emojis.py, in this folder) to upload the emojis to the clean discord server. To run the script you need you need the unzipped emoji export, your discord server name, and your discord bot token, which you will generate below in the course of following the slack-to-discord instructions below (but don't run slack-to-discord on the full slack export yet! just emojis)

	python3 upload_emojis.py --source EMOJIS_EXPORT_FOLDER/ --guild DISCORD_SERVER_NAME --token BOT_TOKEN

3. Used a tool called [slack-to-discord](https://github.com/iqtree/iqtree.github.io) to load the slack export into the discord server, following the directions to create a bot, invite it to the server, etc, exactly. 
	pip install slack-to-discord
	slack-to-discord --zipfile SLACK_EXPORT.zip --guild DISCORD_SERVER_NAME --token BOT_TOKEN

4. Spot-check the discord server, making sure all users, channels, files imported correctly. Make the private channels private again. Now click the little icon of a person beside the general channel, copy the invite link, and share it with MOLE! 

5. Go to Server Settings > Roles and create roles called Director, TA, and faculty. Give each role default access to the revelant private channels, and then assign people their appropriate roles when they join the discord.
